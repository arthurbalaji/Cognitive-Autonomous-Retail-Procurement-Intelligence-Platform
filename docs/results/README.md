# Measured results behind the revised paper

Every number in `CARPIP Research Paper SNS - Camera Ready (revised).docx` comes from a file in this folder. All experiments run **inside the engine image** (`carpip-ml`, Python 3.11, PyTorch 2.4.1 CPU, XGBoost 2.1.1) on one laptop (Intel Core i5-1235U, 16 GB, no GPU, Docker Desktop). Data is the deterministic synthetic generator in `scripts/datagen` (120 SKUs x 3 stores x 150 days; days 0-119 train, days 120-149 are the 30-day evaluation window). Nothing here reproduces the original draft's tables: those were not measurable with this prototype and were replaced.

| File | What it measures | Reproduce |
|---|---|---|
| `forecast_eval.md/json` | Forecast accuracy of LSTM / Transformer / XGBoost / ensemble vs SARIMA, 7-day average and seasonal-naive; rolling origins, 10 seeds, Diebold-Mariano-style tests, 80 % band coverage | `bash scripts/bench/run_in_docker.sh -m scripts.bench.prepare_forecasts --seeds 0-9` then `-m scripts.bench.forecast_eval --seeds 0-9` |
| `procurement_sim.md/json` | 30-day procurement simulation: static EOQ/ROP vs isolated ML vs CARPIP, ablations (MPI, CDIN, negotiation, ranking), two stock regimes, paired tests with Holm correction, sensitivity (supplier reliability, MPI weights +-20 %, LLM price flex, demand volatility) | `... -m scripts.bench.procurement_sim --seeds 0-9 --sensitivity --sens-seeds 0-1` (after `prepare_forecasts --seeds 0-1 --vol 0.25 0.5`) |

## What the measurements say (read before citing)

* **Supported:** holding cost 36 % below static EOQ/ROP; stockouts 62 % below isolated ML ordering; negotiated prices 12.5 points of list price below tier prices; zero price-bound violations in every run; forecast ensemble better than SARIMA (-4.3 % MAE, 10/10 seeds), 7-day average and seasonal-naive; LLM and rule voices agree on every price (the LLM words messages only); input tokens -97.9 % with the compact payload.
* **Fairer tests of the two weakest components (added after the first review):** with wholesalers whose hidden minimum depends on scarcity and price shocks, the MPI still improves price by only 0.09-0.15 points of a 0.5-1.0 point headroom and does not change stockouts; the CDIN test with 12 stores found that the platform's first growth ratio (forecast / recent sales) moved *against* real surges and raised surge-SKU stockouts, while the sales-velocity ratio the paper describes detected the planted surges and cut their stockouts. The node code (`cdin_node/growth.py`) now uses the velocity ratio; the main simulation reports both versions.
* **Not supported by this prototype:** the original draft's headline numbers (78 % stockout reduction, 94.5 % negotiation success, 4.3 % MAPE, 88.8 % cost saving, 42 nodes, 43,000 SKUs). In the simulation the MPI changes prices by about 0.15 points and the CDIN has no detectable effect on stockouts; the CDIN index flagged only about a quarter of planted regional surges with about half false alarms; federated LSTM training was about 4 % less accurate than local-only training; the supplier ranking (not MPI or CDIN) is what reduces stockouts.
* **Caveats:** synthetic data; the simulated wholesalers follow the same bounded protocol the platform uses, so the 12.5-point price effect is protocol-defined, not a market observation; stockout rates are low in absolute terms because the generator starts every store with 12-30 days of cover (a 40 % stock regime is reported alongside); absolute latencies depend on the laptop and load.
* **Bug found by the advanced tests:** the garbage-input property test failed at 10,000 examples (`OverflowError` in `factors._cv` for ~9e307 prices). Fixed in `app/mpi/factors.py` with a regression test; `safety.md` shows both runs.
